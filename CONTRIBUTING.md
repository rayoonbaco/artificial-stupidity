# Contributing

Artificial Stupidity welcomes reproducibility checks, failure cases, domain-specific gate proposals, documentation repairs, and carefully bounded experiments.

Before proposing a change:

1. Preserve the separation between proposer, challenger, evidence, and human authorization.
2. Do not rewrite or delete raw evidence; add a new versioned evidence directory.
3. State the source of truth, predeclare the acceptance boundary, and record failures.
4. Add or update automated tests for decision logic.
5. Distinguish measured facts from inference and product claims.
6. Do not describe a result as safe merely because the gate produced more criticism.

Pull requests should explain the user decision improved, files changed, tests run, known limitations, and recovery path.
